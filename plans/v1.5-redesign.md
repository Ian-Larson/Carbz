# Carbz v1.5 — UI Redesign & UX Rethink

## Problems to Solve

### 1. Desktop layout is wasted space
The current `max-w-md` (427px) single column means the app looks like a phone mockup floating in a sea of gray on desktop. Long vertical scroll to get from ride setup to fuel plan.

### 2. Fuel selection UX is confusing
Users shouldn't have to manually assign mixes to bottles and dial in scoops. The app should either:
- **Auto mode**: "Here's my ride" → app tells you exactly what to bring and when
- **Manual mode**: "I want to use these products" → app calculates amounts and timing

In both cases, the *app* figures out the bottle assignments, scoop counts, and hourly schedule. The user never manually assigns a mix to B1 vs B2.

### 3. Bottle selector is artificially limited
Hard-coded to 2 bottles. Longer rides, courses with aid stations, or riders with extra cage mounts need more. The app should let you specify any number of bottles, while still recommending an ideal combo.

### 4. Duration chip spacing is off
19 duration options (0:30–5:00) in a 7-column grid creates uneven rows and cramped touch targets.

### 5. No way to import a ride from a training plan
Users want to paste "2hr endurance Z2, last 30min at tempo" and get a fuel plan.

## Design: Simplified Fuel Selection UX

### Two Modes: Auto & Manual

#### Auto Mode (default)
User configures ride → app automatically recommends:
- Which drink mix to use and how many scoops per bottle
- Which solids to bring and how many per hour
- Complete bottle prep and hourly schedule

The auto-suggest algorithm (already exists in `suggestions.ts`) becomes the default experience. The fuel plan output section shows the recommendation with an "edit" affordance to tweak individual items.

#### Manual Mode
User toggles to "I'll pick my fuel" → presented with:
- **Product picker**: Checkboxes to select which products to use today (from library)
- **The app still calculates**: Given the selected products, the app determines optimal scoop counts, bottle assignments, and per-hour solid quantities to hit the carb/fluid targets

In *neither* mode does the user manually assign mixes to specific bottles or dial in exact scoop counts. That's the app's job. The user only says "I want to use Skratch and PF chews" and the app figures out the rest.

## Design: Flexible Bottle Configuration

### Remove the 2-bottle hard limit

Replace the current 3-fixed-slot model with a dynamic list:

```
┌──────────────────────────────────────┐
│  🍼 Bottles                          │
│  What bottles are you bringing?      │
│                                      │
│  [550ml ▾] ×1   [−] [+]   🗑️       │
│  [750ml ▾] ×1   [−] [+]   🗑️       │
│                                      │
│  [+ Add bottle]                      │
│                                      │
│  💡 2 bottles on the bike is typical │
│     for rides under 3 hours          │
└──────────────────────────────────────┘
```

**Changes:**
- `BottleSlot[]` becomes a dynamic-length array (not fixed 3 sizes)
- Each slot has a size dropdown (550, 750, 950 — or custom ml input)
- Add/remove buttons for slots
- Soft guidance: "2 bottles typical for < 3hr" / "Consider a third for 3hr+" / "Plan refill stops for 4hr+"
- The calculation engine already handles N bottles — just remove the hard cap

### Type Changes

```typescript
// Before
bottles: [BottleSlot, BottleSlot]  // Fixed tuple

// After
bottles: BottleSlot[]              // Dynamic array
```

Remove `MAX_BOTTLES_ON_BIKE` constant. Add contextual guidance instead of hard limits.

## Design: Improved Duration Selector

### Problem
19 chips in a 7-column grid is cramped and has orphan chips on the last row.

### Solution: Grouped Duration Picker

```
┌──────────────────────────────────────┐
│  ⏱️ Duration                         │
│                                      │
│  Short:    [0:30] [0:45] [1:00]      │
│  Medium:   [1:15] [1:30] [1:45]      │
```

**Changes:**

- Duration options: 0:30, 0:45, 1:00, 1:15, 1:30, 1:45, 2:00, 2:15, 2:30, 2:45, 3:00, 3:30, 4:00, 4:30, 5:00

## Design: Ride from Training Plan

### "Paste Your Workout" Input

Add a text area at the top of ride setup where users can paste workout descriptions:

```
┌──────────────────────────────────────┐
│  📋 Quick Setup                      │
│                                      │
│  ┌──────────────────────────────┐    │
│  │ Paste your workout...        │    │
│  │ e.g., "2hr endurance Z2,    │    │
│  │  last 30min at tempo"       │    │
│  └──────────────────────────────┘    │
│  [Parse Workout]                     │
│                                      │
│  ── or configure manually below ──   │
└──────────────────────────────────────┘
```

### Parsing Strategy

Simple keyword extraction (no AI needed):

| Pattern | Extracts |
|---------|----------|
| `2hr`, `2 hours`, `90min`, `1:30` | Duration |
| `Z1`, `Z2`, `recovery`, `endurance` | Intensity: easy |
| `Z3`, `tempo`, `sweet spot` | Intensity: hard |
| `Z4`, `Z5`, `threshold`, `VO2`, `race` | Intensity: race |
| `hot`, `warm`, `cool`, `cold` | Condition |
| `group ride`, `race`, `crit` | Intensity: race |

After parsing, auto-populate the ride config selectors. User can then tweak anything that was parsed wrong.

### Implementation

New file: `src/lib/workoutParser.ts`

```typescript
interface ParsedWorkout {
  durationMinutes: number | null;
  intensity: Intensity | null;
  condition: Condition | null;
  confidence: 'high' | 'medium' | 'low';
  rawText: string;
}

export function parseWorkout(text: string): ParsedWorkout;
```

## Design: Revamped Header & Navigation

### Replace Tab Bar with Compact Header

The "Calculator | My Library" tab paradigm separates things that should be together. Replace with:

```
┌──────────────────────────────────────────────────┐
│  🚴 Fuel Calculator                              │
│  Dial in your on-bike nutrition                  │
│                                                  │
│  [📦 Presets ▾]  [📚 Library]  [⚙️ Settings]    │
└──────────────────────────────────────────────────┘
```

- **Presets dropdown**: Quick-load saved ride configs (opens a dropdown, not a page)
- **Library**: Opens a slide-over panel / modal (not a full tab switch)
- **Settings**: Preferences (body weight, sweat rate, defaults)

This keeps the user on the calculator at all times. Library and settings are overlays, not separate pages.
